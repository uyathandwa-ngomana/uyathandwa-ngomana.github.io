## 3. Ways of Working

### 3.1 Agile Framework

The team follows an Agile approach to organise development tasks, monitor progress, identify issues, and improve functionality through implementation and testing.

The work is organised around the tasks that need to be completed, with progress reviewed as features are developed and errors are investigated.

### 3.2 Team Activities

| Activity | Purpose |
|---|---|
| Progress updates | Share completed work, upcoming tasks, and challenges. |
| Task planning | Identify and organise the work that needs to be completed. |
| Development | Implement required features and improve existing functionality. |
| Testing | Check that features work correctly and identify errors. |
| Debugging | Investigate and resolve issues affecting system functionality. |
| Feedback and review | Identify improvements and determine the next steps. |

## 4. Working Agreements

- Complete assigned tasks within agreed deadlines.
- Communicate progress and raise challenges when they occur.
- Test changes to check that the affected functionality works correctly.
- Investigate backend errors and work towards resolving them.
- Keep project tasks and progress records updated.
- Consider feedback and use it to improve the quality of the work.
- Ask for guidance when an issue cannot be resolved independently.
- Avoid marking a feature as complete before the relevant functionality has been checked.

## 5. Communication

- **Progress updates:** Share completed tasks, planned work, and any blockers.
- **Technical issues:** Explain errors clearly and discuss possible solutions with the team or supervisor.
- **Feedback:** Use feedback to improve the application and address outstanding issues.
- **Task coordination:** Keep team members informed about progress and work that may affect other parts of the system.
- **Documentation:** Record important changes, completed tasks, and unresolved issues.

## 6. Decision-Making

Development decisions should consider the project requirements, the existing system design, and feedback from the team and supervisor.

When a technical issue occurs, the relevant functionality should be investigated and tested before a solution is implemented.

Issues that cannot be resolved independently should be discussed with the relevant team member or supervisor. Decisions affecting project requirements or major functionality should be reviewed with the supervisor where necessary.

## 7. Definition of Done (DoD)

A task can be considered complete when:

- The implementation meets the task requirements.
- The affected functionality has been tested.
- Identified errors have been fixed or documented for further investigation.
- Changes work with the relevant parts of the application.
- The task status and progress have been updated.
- The work is ready for review where required.

For ProKonecta, testing should consider the relevant customer or professional workflow, such as authentication, saving profile details, posting service requests, or accessing marketplace functionality.

## 8. Core Values & Behaviours

- **Respect** — Listen to team members and consider their feedback.
- **Communication** — Share progress, questions, and challenges clearly.
- **Accountability** — Take responsibility for assigned tasks and follow through on them.
- **Teamwork** — Cooperate with others to achieve project goals.
- **Transparency** — Report progress and technical problems honestly.
- **Continuous learning** — Learn from errors and use challenges to improve technical skills.
- **Quality** — Test changes and aim for reliable, working functionality.

## 10. Review & Improvement

The team charter should be reviewed when project requirements, responsibilities, or working methods change.

Lessons learned during development and testing can be used to improve task planning, communication, error handling, and the quality of future changes.
